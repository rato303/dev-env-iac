# コミット作成スキル

このスキルは、dev-env-iacプロジェクトでGitコミットを作成するプロセスを自動化します。

## ワークフロー

### Phase 1: 変更内容の確認

以下のコマンドを**並列実行**して現在の変更を把握します：

1. `git status` - 変更ファイルとステータスを確認
2. `git diff --staged` - ステージング済み変更の差分を取得
3. `git diff` - 未ステージング変更の差分を取得

**出力**:
- 変更ファイル一覧
- ステージング状態
- 変更内容の差分

### Phase 2: コミットメッセージ生成

1. **変更内容を分析**：
   - `git diff`の出力から変更の性質を判断
   - 新機能追加、バグ修正、リファクタリング、ドキュメント更新などを識別
   - 変更ファイルのパスとファイル名から対象領域を特定

2. **プレフィックスを決定**：
   - `feat:` - 新機能追加（新規ファイル、新しい機能実装）
   - `fix:` - バグ修正（エラー修正、不具合対応）
   - `refactor:` - リファクタリング（動作変更なしのコード改善）
   - `docs:` - ドキュメント更新（*.mdファイルのみの変更）
   - `chore:` - ビルド、設定変更（package.json、Makefile等）
   - `test:` - テスト追加・修正（テストファイルのみの変更）

3. **コミットメッセージを生成**：
   - 形式: 1-2文で「何を」「なぜ」変えたかを簡潔に記述
   - 日本語または英語（変更内容に応じて適切な方を選択）
   - 本文に変更ファイルと修正内容を箇条書き
   - 必ず末尾に以下を追加：
     ```
     Co-Authored-By: Claude Code <noreply@anthropic.com>
     ```

### Phase 3: コミット実行

1. **未ステージング変更をステージング**（必要な場合）：
   ```bash
   git add <変更されたファイル>
   ```

2. **コミット作成**：
   ```bash
   git commit -m "$(cat <<'EOF'
   <コミットメッセージ本文>

   Co-Authored-By: Claude Code <noreply@anthropic.com>
   EOF
   )"
   ```

3. **コミットハッシュを取得**：
   ```bash
   git log -1 --format=%H
   ```

4. **ユーザーに報告**：
   - 「コミットを作成しました: <hash>」
   - コミットメッセージの要約を表示

## エラーハンドリング

### 変更がない場合

**検出方法**:
```bash
git status --short
```

**エラーメッセージ**:
```
コミットする変更がありません。

変更を行ってから再度実行してください。
```

### ステージングエラー

**検出方法**:
`git add`コマンドが非ゼロで終了

**エラーメッセージ**:
```
ファイルのステージングに失敗しました。

考えられる原因:
- ファイルが存在しない
- ファイル名が間違っている
- 権限エラー
```

### コミット失敗

**検出方法**:
`git commit`コマンドが非ゼロで終了

**エラーメッセージ**:
```
コミットの作成に失敗しました。

考えられる原因:
- Git設定エラー（user.name, user.email未設定）
- pre-commit フックの失敗
- コミットメッセージが空
```

**解決方法**:
```bash
# Git設定確認
git config user.name
git config user.email

# 未設定の場合
git config user.name "Your Name"
git config user.email "your.email@example.com"
```

## 使用例

### 例1: 未ステージング変更からコミット作成

**ユーザー**: "変更をコミットして"

**スキルの動作**:
1. `git status` → SKILL.md が modified
2. `git diff SKILL.md` → 差分を分析
3. コミットメッセージ生成: "feat: コミット作成スキル追加"
4. `git add .claude/skills/committing/SKILL.md`
5. `git commit`
6. コミットハッシュ取得: `7a8b9c0...`
7. "コミットを作成しました: 7a8b9c0"

### 例2: ステージング済み変更からコミット作成

**ユーザー**: "コミットを作成"

**スキルの動作**:
1. `git status` → Changes to be committed: SKILL.md
2. `git diff --staged` → ステージング済み差分を分析
3. コミットメッセージ生成（ステージング済みファイルのみ対象）
4. `git commit`（git add不要）
5. "コミットを作成しました: 8c9d0e1"

### 例3: 変更がない場合

**ユーザー**: "コミットして"

**スキルの動作**:
1. `git status --short` → (empty)
2. エラー検出: 変更なし
3. メッセージ: 「コミットする変更がありません。変更を行ってから再度実行してください。」

## プロジェクト固有の規約

### コミットメッセージ形式

- **プレフィックス**: 必須（feat, fix, refactor, docs, chore, test）
- **本文**: 変更内容を箇条書き（ファイル名: 修正内容）
- **Co-Authored-By**: 必須 - `Co-Authored-By: Claude Code <noreply@anthropic.com>`

**良い例**:
```
feat: コミット作成スキル追加

- SKILL.md: スキル定義作成
- workflow.md: ワークフローリファレンス作成

Co-Authored-By: Claude Code <noreply@anthropic.com>
```

**悪い例**:
```
update
```
（プレフィックスなし、詳細なし、Co-Authored-Byなし）

### プレフィックス判定ルール

| プレフィックス | 条件 |
|-----------|------|
| `feat:` | 新規ファイル追加、新機能実装 |
| `fix:` | バグ修正、エラー修正、レビュー指摘対応 |
| `refactor:` | コード構造改善（動作変更なし） |
| `docs:` | *.mdファイルのみの変更 |
| `chore:` | package.json、Makefile、設定ファイル |
| `test:` | テストファイルのみの変更 |

複数種類の変更がある場合は、主要な変更を基準にプレフィックスを決定します。

### 言語選択

- **日本語**: ドキュメント、スキル、設定ファイルの変更
- **英語**: コードファイル（.ts, .py等）の変更が主な場合

### ステージング戦略

- **未ステージング変更がある場合**: 自動的に `git add` でステージング
- **ステージング済み変更のみの場合**: そのままコミット
- **両方ある場合**: 全てステージングしてコミット
