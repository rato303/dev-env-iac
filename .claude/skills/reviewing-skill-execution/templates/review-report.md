## 優先度の定義

| 優先度 | 基準 | 対応タイミング |
|--------|------|----------------|
| **High** | トークン削減効果 >30%、またはユーザー体験への影響が大 | 即座に対応推奨 |
| **Medium** | トークン削減効果 10-30%、実装が容易 | 次回のスキル更新時に対応推奨 |
| **Low** | トークン削減効果 <10%、将来的な改善余地 | オプション（必要に応じて対応） |

## カテゴリの定義

### 効率性（Efficiency）
- 重複ファイル読み込み
- 直列実行の非効率
- 不要なツール呼び出し
- ファイルI/O最適化の欠如

### 品質（Quality）
- 規約違反
- エラーハンドリングの欠如
- 不適切なエラーメッセージ
- テスト不足

### ユーザー体験（User Experience）
- 不要な確認プロンプト
- 不明瞭な実行ステップ
- 不十分なフィードバック
- 結果報告の分かりにくさ

## トークン削減効果の見積もり方法

### 1. ファイル読み込みの重複

```
削減トークン = (重複回数 - 1) × ファイルサイズ（文字数） × 0.75
※ 0.75は、文字数→トークン数の概算係数（1トークン ≈ 4文字）
```

**例**:
- 3000文字のファイルを3回読む
- 削減トークン = (3 - 1) × 3000 × 0.75 = 4500トークン
- 総トークン使用量が10000トークンの場合、45%削減

### 2. 並列実行化

```
トークン削減効果 = 0（並列化自体ではトークンは削減されない）
実行時間短縮効果 = 約50-70%（2-3個の独立したコマンドを並列化した場合）
```

**注**: 並列化は主に実行速度の改善であり、トークン削減ではない点に注意

### 3. 部分読み込み（offset/limit）

```
削減トークン = (全体サイズ - 部分サイズ) × 0.75
```

**例**:
- 5000行のファイルの末尾100行のみ必要
- 削減トークン = (5000 - 100) × (平均行長80文字) × 0.75 = 約294,000トークン

### 4. エラーハンドリングの改善

```
削減トークン = 失敗時の無駄な処理のトークン × 失敗確率
```

**例**:
- 事前チェックなしの場合、エラー発生まで2000トークン消費
- 事前チェックありの場合、100トークンで早期検出
- 失敗確率20%の場合: (2000 - 100) × 0.2 = 380トークン削減（期待値）

## 使用例

### 例1: 重複ファイル読み込みの検出

```markdown
## スキル実行レビュー: creating-issue

### 分析結果
実行は概ね機能的ですが、効率性に改善の余地があります。特に、ファイル読み込みの重複が顕著です。

### 検出された問題点

#### 同一ファイルの重複読み込み (High)
- **カテゴリ**: 効率性
- **詳細**: `config/projects.yaml` を3回読み込んでいます（Phase 1, Phase 2, Phase 3でそれぞれ1回）
- **影響**: 不要なトークン消費
- **トークン使用量**: 約9000トークン（削減可能: 6000トークン、67%削減）

### 改善提案

#### 同一ファイルの重複読み込みへの対応

**Before**:
Phase 1-3でそれぞれファイルを読み込み

```
Phase 1: Read config/projects.yaml → issue内容生成
Phase 2: Read config/projects.yaml → テンプレート選択
Phase 3: Read config/projects.yaml → メタデータ設定
```

**After**:
Phase 1でのみ読み込み、以降は変数を参照

```
Phase 1: Read config/projects.yaml → 変数projectsに格納
Phase 2: 変数projectsを参照 → テンプレート選択
Phase 3: 変数projectsを参照 → メタデータ設定
```

**実装方法**:
1. Phase 1の冒頭で `projects = Read("config/projects.yaml")` を実行
2. Phase 2-3では `projects` 変数を参照
3. SKILL.mdに「Phase 1でファイル内容を変数に格納し、以降は再利用」と明記

**トレードオフ**:
- **利点**: トークン削減、実行速度向上
- **欠点**: なし（ファイル内容が実行中に変更されることは想定されない）

### スキル定義への反映提案

#### SKILL.mdの修正

**ファイル**: `.claude/skills/creating-issue/SKILL.md`

**修正箇所**: Phase 1 - issue内容の準備

+- Phase 2以降では、ファイルシステムに再度アクセスせず、変数を参照
+
 #### ケース1: ユーザーから直接指示がある場合
 ...
```

### 効果の見積もり

この改善により、以下の効果が期待されます：

- **トークン削減**: 約6000トークン（67%削減）
- **実行時間**: 約0.5秒短縮（Read tool callの削減）
- **ユーザー体験**: 実行速度の向上により、よりスムーズな体験

### 次のステップ

1. [ ] SKILL.mdの修正を適用
2. [ ] 他のスキル（planning-from-issue, responding-review）にも同様の最適化を検討
3. [ ] 修正後の動作確認
4. [ ] ベストプラクティスとして `references/best-practices.md` に追記

## 注意事項

1. **保守的な見積もり**: トークン削減効果は保守的に見積もり、「約」「推定」の表記を使用
2. **改善点なしも正当な結果**: 無理やり問題を指摘しない
3. **優先度の明確化**: High/Medium/Lowを明確に区別
4. **実装可能性**: 提案は実際に実装可能な内容に限定
5. **トレードオフの明示**: 改善の利点だけでなく、欠点（あれば）も記載
