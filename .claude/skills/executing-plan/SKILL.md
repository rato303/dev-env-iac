# 作業計画実行スキル

このスキルは、dev-env-iacプロジェクトで作業計画ファイル（planning-from-issueスキルが生成）に基づいて実装作業を段階的に進めます。

## ワークフロー

### Phase 1: プランファイル読み込みと検証

以下のコマンドを実行してプランファイルの状態を確認します：

1. プランファイルパスを取得（引数または対話的に指定）
2. ファイル存在確認
3. 実行メタデータセクションを解析
4. 現在の状態（pending/in-progress/completed）を取得
5. 現在のフェーズ番号を取得

**出力**:
- プランファイルパス
- 現在の状態
- 現在のフェーズ
- Issue番号とタイトル

### Phase 2: フェーズ抽出と実行準備

1. **実装ステップセクションを抽出**：
   - `## 実装ステップ` セクションを検索
   - `### Phase 1:` ~ `### Phase 4:` を抽出
   - 各フェーズの Goal, Tasks, Files, Commands を解析

2. **実行計画を提示**：
   - 現在のフェーズから実行すべきフェーズを特定
   - ユーザーに実行計画を提示
   - 各フェーズの概要を表示

3. **ユーザー確認**：
   - 「どのフェーズから実行しますか？」と確認
   - 現在のフェーズ番号をデフォルトとして提示

### Phase 3: フェーズ実行とメタデータ更新

1. **フェーズを順次実行**：
   - 指定されたフェーズから開始
   - 各フェーズの Goal を表示
   - Tasks を一覧表示
   - ユーザーに「このフェーズを実行しますか？」と確認

2. **実装作業**：
   - Tasks に従ってファイルを作成・編集
   - 必要に応じてコマンドを実行
   - Claude が自動的に作業を進める（ユーザーは確認のみ）

3. **メタデータ更新**：
   - Current Phase を更新
   - State を "in-progress" に更新
   - Files Modified にファイルを追加
   - Commits にコミットハッシュを追加（コミット時）
   - Phase Checklist を更新（完了したフェーズにチェック）

4. **次のフェーズへ**：
   - フェーズ完了後、次のフェーズへ進むか確認
   - すべてのフェーズが完了したら Phase 4 へ

### Phase 4: 完了確認とレポート

1. **完了状態を記録**：
   - State を "completed" に更新
   - 最終更新日時を記録

2. **実行サマリーを出力**：
   - 変更ファイル数
   - コミット数
   - 実行時間

3. **次のステップ提案**：
   - PR作成の提案
   - レビュー依頼の提案

## エラーハンドリング

### Plan File Not Found

**検出方法**:
```bash
if [ ! -f "$PLAN_FILE" ]; then
  # プランファイルが存在しない
fi
```

**エラーメッセージ**:
```
Plan file not found: {パス}

Please verify:
- Plan file path is correct
- You are in the correct directory
- Plan file was generated by planning-from-issue skill

Run 'ls ~/.claude/plans/' to see available plan files.
```

### Invalid Plan Format

**検出方法**: 必須セクション（実行メタデータ、実装ステップ）が存在しない

**エラーメッセージ**:
```
Invalid plan file format: {パス}

The plan file is missing required sections:
- ## 実行メタデータ
- ## 実装ステップ

Please regenerate the plan using planning-from-issue skill.
```

### Already Completed

**検出方法**: State が "completed"

**エラーメッセージ**:
```
Plan is already completed: {パス}

Current state: completed
All phases: [x] Phase 1, [x] Phase 2, [x] Phase 3, [x] Phase 4

To re-execute, manually reset the metadata or create a new plan.
```

### Phase Execution Failed

**検出方法**: ファイル作成・編集中にエラー

**エラーメッセージ**:
```
Phase {番号} execution failed.

Error: {エラー詳細}

The plan state has been saved. You can:
1. Fix the issue and re-run the skill
2. Manually complete the phase and update metadata
3. Cancel and review the plan
```

### Metadata Update Failed

**検出方法**: プランファイルの書き込みエラー

**エラーメッセージ**:
```
Failed to update plan metadata: {パス}

Error: {エラー詳細}

The implementation may have succeeded, but progress was not recorded.
Please manually update the metadata or re-run the phase.
```

## 使用例

### 例1: プランを最初から実行

**ユーザー**: "~/.claude/plans/issue-4-planning-from-issue-skill.md のプランを実行して"

**スキルの動作**:
1. プランファイルを読み込み
2. メタデータ確認: State=pending, Current Phase=0
3. 実行計画提示:
   ```
   Plan: Issue #4 - planning-from-issue スキル実装
   
   Implementation phases:
   - Phase 1: プランファイル読み込みと検証
   - Phase 2: フェーズ抽出と実行準備
   - Phase 3: フェーズ実行とメタデータ更新
   - Phase 4: 完了確認とレポート
   
   Current phase: 0 (not started)
   Start from: Phase 1
   ```
4. ユーザー確認: 「Phase 1 から実行しますか？ [y/n]」
5. Phase 1 実行: ファイル作成、コミット
6. Phase 2 実行: ...
7. 完了: State=completed

### 例2: 中断したプランを再開

**ユーザー**: "プランの続きを実行"

**スキルの動作**:
1. プランファイルを読み込み（前回のプランを自動検出または指定）
2. メタデータ確認: State=in-progress, Current Phase=2
3. 実行計画提示:
   ```
   Plan: Issue #4 - planning-from-issue スキル実装
   
   Progress:
   - [x] Phase 1: プランファイル読み込みと検証
   - [x] Phase 2: フェーズ抽出と実行準備
   - [ ] Phase 3: フェーズ実行とメタデータ更新
   - [ ] Phase 4: 完了確認とレポート
   
   Current phase: 2 (in progress)
   Resume from: Phase 3
   ```
4. Phase 3 から再開

### 例3: プランファイルが見つからない

**ユーザー**: "~/.claude/plans/issue-999-nonexistent.md を実行"

**スキルの動作**:
1. ファイル存在確認
2. エラー検出: ファイルが存在しない
3. エラーメッセージ:
   ```
   Plan file not found: ~/.claude/plans/issue-999-nonexistent.md
   
   Run 'ls ~/.claude/plans/' to see available plan files.
   ```

## プロジェクト固有の規約

### プランファイル形式

- **Location**: `~/.claude/plans/`
- **Format**: `issue-{番号}-{slug}.md`
- **必須セクション**:
  - `## 実行メタデータ`
  - `## 実装ステップ`
  - `### Phase 1:` ~ `### Phase 4:`

### メタデータフィールド

```markdown
## 実行メタデータ

- **状態**: pending / in-progress / completed
- **現在のフェーズ**: 0-4
- **ブランチ**: feature/{slug}
- **変更ファイル**: [{ファイルパス}, ...]
- **コミット**: [{コミットハッシュ}, ...]
- **最終更新**: {ISO8601タイムスタンプ}

### フェーズチェックリスト
- [ ] Phase 1: {phase name}
- [ ] Phase 2: {phase name}
- [ ] Phase 3: {phase name}
- [ ] Phase 4: {phase name}
```

### 状態遷移

```
pending → in-progress → completed
           ↑____________↓
          (中断・再開)
```

### ブランチ戦略

- プラン実行時に feature ブランチを作成（まだ存在しない場合）
- ブランチ名はプランファイルのメタデータから取得
- 既に正しいブランチにいる場合はスキップ

### コミット戦略

- 各フェーズ完了時にコミットを作成（オプション）
- コミットメッセージ形式:
  ```
  feat: {プラン名} - Phase {番号} 完了
  
  - {変更内容1}
  - {変更内容2}
  
  Co-Authored-By: Claude Sonnet 4.5 <noreply@anthropic.com>
  ```
